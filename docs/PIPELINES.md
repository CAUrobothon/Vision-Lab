# 내장 파이프라인 (`backend/cubevision`)

OpenCV 고전 파이프라인 4개와 모든 모델이 함께 쓰는 후처리·색 판정을 정리한 문서다.
출발점은 `docs/research/classical-cv.json`(장면 기하, 후보 파이프라인 5개, 공용 후처리 8단계, 색 분류)이고,
구현하면서 측정으로 바꾼 부분은 마지막 절에 따로 적었다.

> **합성 데이터 기준, 실제 사진 성능은 랩에서 확인 필요.**
> 이 문서의 숫자는 모두 `cubevision.synth`가 그린 합성 장면에서 잰 것이다. 배관이 맞게 이어졌는지,
> 기하 계산에 버그가 없는지는 보여 주지만, 인쇄 종이·실제 조명·실제 렌즈에서 얼마나 맞는지는 보여 주지 못한다.

## 1. 한눈에

| 키 | 이름 | 한 줄 | 강한 곳 | 약한 곳 |
|---|---|---|---|---|
| `cv.hsv_ranges` | HSV 색 범위 | 색마다 H·S·V 하한–상한, 통과한 범위가 곧 색 | 가장 빠름, 슬라이더로 바로 맞춤 | 노출이 바뀌면 S·V 문턱을 다시 맞춰야 함 |
| `cv.board_diff_lab` | 판 차이 + Lab 최근접색 | 판과 채도가 다른 픽셀 = 전경, 픽셀마다 가장 가까운 기준색 | 그림자·조명 변화에 강함, 색이 다른 큐브가 붙어도 저절로 나뉨 | 판과 채도 차이가 작은 옅은 나무 |
| `cv.edge_quads` | 윤곽으로 닫힌 사각형 | 색을 보지 않고 윤곽이 둘러싼 윗면 크기 영역을 찾은 뒤 색을 읽음 | 색 문턱이 없어 화이트밸런스에 덜 민감, 중심이 가장 정확 | 윤곽이 끊기면(흐림·약한 대비) 놓침, 흰 판 위 나무 |
| `cv.lab_autocluster` | Lab 자동 군집 | 판을 뺀 픽셀을 k-평균으로 묶고 기준색 이름을 붙임 | 색 문턱이 전혀 없음, 군집 중심이 기준색 후보로 나옴 | 가장 느림, 군집 수와 장면이 안 맞으면 흔들림 |

처음 써 볼 때는 `cv.board_diff_lab`을 기본으로 두고, 같은 사진에서 나머지 셋과 나란히 비교하는 것을 권한다.

## 2. 공통 흐름

모든 파이프라인은 같은 틀(`pipelines/common.py`의 `BlobPipeline`)을 쓴다. 파이프라인마다 다른 것은 2단계뿐이다.

1. **판 색 측정과 조명 보정** (`colour.colour_model`) — 밝은 픽셀 가운데 가장 무채색에 가까운 픽셀의 중앙값을 판 색으로 잰다.
   기준색을 고른 사진의 판 색(`proto_board`)과의 채널별 비율(gains)로 영상을 "기준색을 고른 조명"으로 되돌린다.
   화이트밸런스·노출 변화가 상쇄되고, 회색 물체(기둥·팔·바닥)는 색이 낀 조명에서도 회색으로 남는다.
2. **후보 만들기** — 파이프라인마다 다른 방식으로 후보 덩어리(마스크)를 만든다. 검출 영역(ROI) 밖은 여기서 지운다.
3. **공용 후처리** (`postprocess.cubes_from_blobs`) — 아래 3절.
4. **검출 영역 필터** — 중심이 ROI 밖인 큐브를 뺀다.
5. 결과: 큐브 목록, 단계별 시간(`stages_ms`), 짧은 경고(`notes`), 요청하면 디버그 레이어.

디버그 레이어 규칙: 1채널(HxW, 0/255)은 마스크(화면에서 색을 입혀 겹침), 3채널은 그대로 보는 그림(어둡게 한 원본 위에 그림).
모든 파이프라인에 `candidates`(후보와 윗면) 그림이 있다. 윤곽선 색: 초록 = 큐브, 하늘 = 나눔, 빨강 = 큰 영역,
주황 = 가는 띠, 회색 = 판·그림자 색, 자홍 = 다른 큐브의 옆면. 흰 사각형 = 최종 윗면.

### 파라미터는 전부 공개한다 (2026-11-25)

결과(찾는 큐브, 위치, 각도, 색, 점수)를 바꾸는 값은 모두 파라미터다. 숨은 상수도, 한쪽 끝만 보여 주는 범위도 두지 않는다.
연산이 받는 형태 그대로 보여 준다(예: `cv2.inRange`는 H·S·V 각각 하한과 상한). 기본값은 측정에 쓴 값 그대로라서,
기본값으로는 공개 전과 결과가 같다(합성 장면 48개 × 파이프라인 4개 + 외부 모델 변환 함수 출력이 바이트 단위로 같음).
`tests/cubevision/test_cv_params.py`가 보여 주는 파라미터를 파이프라인이 모두 실제로 읽는지, 각 값을 범위 양 끝으로 바꿔도 실행되는지 확인한다.

| 묶음 | 내용 | 어디서 |
|---|---|---|
| 색 기준 | 기준색 4개·판 색, 조명 보정 켜기, 최소 채도, 기준색 최대 거리 | `colour.py` |
| 색 판정 세부 | L\* 가중치, 확률 폭 σ, 어두움 기준, 약한 채도 배수, 색 읽기 안쪽 여백 | `colour.py`, 후처리 6단계 |
| 판 색 측정 | 보정 배율 한계, 판 후보 V·S 백분위, S 하한, 표본 수 | `colour.board_colour` |
| 크기·모양 | 윗면 한 변, 최소·최대 크기, 가는 띠, 가려짐 기준, 윗면 채움 최소, 구멍 메우기와 한도, 덩어리 연결(4/8) | 후처리 1단계 |
| 카메라 | 주점(화면 중심/직접 입력), 큐브 높이·카메라 높이(κ = 둘의 비), 화면 테두리 거리 | 후처리 3~5단계 |
| 윗면 찾기 | 가장자리 기준, 옆면 띠 허용, 밝기 경계 사용·최소 차이·찾는 구간·단면 최소 폭·비교 폭 | 후처리 3~4단계 |
| 붙은 큐브·각도 | 나누기 켜기, 한 개로 보는 최대 길이, 빈틈없는 묶음 기준, 묶음 칸 최소 채움, 워터셰드 씨앗 깊이, k-평균 반복, 각도 불일치 기준, 윤곽선 단순화, 옆면 후보 버리기와 비율 | 후처리 2~5단계 |
| 가려진 큐브 | 진짜 모서리 밝기 차, 바깥 밝기 재는 거리·표본 수, 가로 표본 수, 양끝 제외 | 후처리 4b단계 |
| 점수 | 가려진 큐브·테두리 큐브 점수 배율 | 후처리 7단계 |
| 전처리 등 | 흐림 크기·시그마, 열기·닫기 크기·반복·커널 모양, 파이프라인별 값(5절) | 각 파이프라인 |
| 박스 → 윗면 | (학습 모델 detect) 주변 여유, 씨앗 색 영역, L\* 가중치, 색 거리 문턱 범위, 마스크 크기 허용, 흐림 | `cube_from_box` |

학습한 `.pt` 모델은 Ultralytics 8.4.215의 예측 인자 가운데 결과나 속도를 바꾸는 것을 모두 보여 준다:
`conf, iou, imgsz(정사각 또는 [h, w]), rect, max_det, classes, agnostic_nms, augment, nms, tile, batch, device, quantize, compile, channels_last`,
segment는 `retina_masks`. `quantize·nms·device·compile·channels_last`는 Ultralytics가 예측기를 만들 때만 읽으므로 바꾸면 예측기를 새로 만든다.
그 뒤 랩 자체의 후처리 파라미터(색 기준·색 판정 세부·판 색 측정, segment·detect는 윗면 맞추기, detect는 박스 → 윗면)가 이어진다.
학습 모델의 검출은 버리거나 나누지 않으므로 그런 문턱(최소·최대 크기, 가는 띠, 나누기, 옆면 후보)은 없다.

**값 규칙** (`types.resolve_params`, 실행·미리보기·프리셋·JSON 적용 모두 같음): 숫자는 [최소, 최대]로 자르고 최소에서 시작하는
간격(step) 격자에 맞춘다(슬라이더에 보이는 값 = 실제로 쓰는 값, 예: 홀수만 되는 커널 크기 8 → 9). 범위(range)는 두 끝을 각각 [최소, 최대]로
잘라 하한이 상한보다 커지는 일이 없다([600, 700] → [500, 500]). 선택(select)은 숫자로 써도 그 보기로 읽고(5 → "5"), 보기에 없는 값은
기본값으로 바꾸지 않고 오류로 알린다. 모든 기본값은 이 규칙에서 그대로 남는다(테스트로 확인).

**파라미터로 내보내지 않은 것** (결과를 바꾸지 않거나 공식의 일부인 것):
- 공식 상수: 밝기 가중치 0.114·0.587·0.299, 8비트 Lab 변환(×2.55, +128), 90° 주기, 서브픽셀 시프트 16, 0 나누기 방지값.
- 결과를 바꿀 수 없는 사전 거르기: 덩어리를 만들 때 최소 크기의 절반 미만을 미리 버리는 것(후처리 1단계가 어차피 버림), `edge_quads`의 √2 똑바른 상자 사전 검사.
- 경고 문구 문턱(포화 2 %, 판 L\* 45, 판 채도 12, 포화 판정 250)과 디버그 그림의 색·배율, 원래 외곽선(`polygon`) 단순화 1 px.
- 측정이 불가능할 때의 하한(판 후보 50·25픽셀), 박스 마스크의 Otsu 히스토그램 해상도(0.5 Lab), 분할 k-평균의 수렴 허용 0.05 px,
  밝기 경계 탐색의 끝 여유 2 px, `edge_quads`가 윤곽 두께만큼 영역을 다시 키우는 3×3 커널(반복 = 틈 메우기 + 1),
  자동 군집 '기준색에서 시작'의 여분 중심 고르는 규칙과 시도 1회.
- Ultralytics: 파일 저장·화면 표시(`save*`, `show*`, `visualize`, `embed`, `line_width`), 소스 읽기(`source`, `stream_buffer`, `vid_stride` — 랩이 프레임을 직접 읽음),
  `dnn`(ONNX 전용), `nms=True`(내보내기 전용).

## 3. 공용 후처리 (모든 모델 공용)

카메라가 판을 똑바로 내려다보므로 큐브 덩어리 = 윗면 + 원근으로 보이는 옆면 띠다. 윗면은 주점(영상 중심)에서 먼 쪽에 있다.

| 단계 | 하는 일 | 이유 |
|---|---|---|
| 1 거르기 | 윗면 넓이(`face_px²`)의 0.35배 미만 = 잡음, `max_area_ratio`배 초과 = 큰 영역(바구니 바닥·팔), 짧은 변이 0.6면 미만 = 옆면 띠 | 바구니 바닥은 같은 종이라 색으로는 못 거름 |
| 2 거친 각도 | `cv2.boxPoints(cv2.minAreaRect(외곽선))`의 한 변 방향, 90° 주기 | 사각형 각도 필드는 OpenCV 버전마다 범위가 달라 쓰지 않음. PCA는 정사각형에서 방향이 없음 |
| 3 개수 세기·나누기 | 큐브 좌표계에서 1px 단면 개수로 두 변의 길이를 재고, 예측한 옆면 띠(κ·주점까지 거리)를 뺀 뒤 몇 개인지 셈. 꽉 찬 묶음은 바깥 모서리부터 윗면 크기로 타일, 한 줄로 어긋난 묶음은 윗면 폭으로 자름, 나머지(L자 등)는 넓이로 개수를 정해 거리변환 워터셰드 → k-평균. 넓이로 셀 때 띠는 잰 길이에 실제로 남는 만큼만 더함 | 1.6면까지는 한 개(9단 탑의 윗면이 1.53면). 윗면만 종이면 나무 옆면은 덩어리 밖이라 띠가 없다: 예측 띠를 그대로 더하면 같은 색 L자 3개를 2개로 셌다(합성 96건 중 62건) |
| 4 윗면 | 주점에서 가장 먼 쪽 모서리에 윗면 크기 정사각형을 매닮. 띠가 없으면 잰 경계를 그대로. 밝기 경계(윗면은 밝고 옆면은 어두움)가 보이면 그 경계로 크기를 맞춤(탑 윗면) | 합성 단일 큐브 80개(종이 윗면만/모든 면 × 깨끗/잡음): 덩어리 중심 평균 3.3~5.7 px → 이 방식 0.5~0.8 px, 각도 평균 0.1~0.3° |
| 4b 가려진 큐브 | 한 변이 0.85면보다 짧으면 `partial`. 바깥이 밝은 판인 쪽 경계를 진짜로 보고 정사각형을 매닮. 판단이 안 서면 덩어리 중심만, 각도 없음 | 팔은 어둡고 판은 밝음 |
| 5 옆면 제거 | 다른 큐브의 실루엣(윗면 + 주점 쪽으로 κ만큼 당긴 밑면의 볼록 껍질) 안에 절반 이상 들어가는 후보를 뺌 | 윗면만 색종이일 때 나무색 옆면 띠가 나무 큐브로 잡히는 것 방지 |
| 6 색 | 윗면을 15 % 줄인 영역의 중앙값 색 → 보정 → 가장 가까운 기준색. 판·그림자·어두운 회색이면 후보를 버림 | 아래 4절 |
| 7 출력 | `quad`(시계 방향, x+y 최소 꼭짓점부터), `center`, `angle`(0 이상 90° 미만), 플래그 | `types.py` 계약. 아주 작은 음수 각도를 `% 90`으로 접으면 90.0이 나오므로 0으로 접음 |

플래그 뜻: `side_band` 옆면 띠를 잘라 냄, `shade_edge` 밝기 경계로 윗면 크기를 맞춤, `large_face` 윗면이 `face_px`보다 큼(탑 또는 `face_px` 오차),
`split` 붙은 덩어리에서 나눔, `partial` 일부가 가려짐(점수 절반), `touches_border` 화면 가장자리에 닿음,
`class_mismatch` 모델/게이트가 정한 색과 픽셀 색이 다름, `no_colour` 외부 모델 검출인데 픽셀이 판 색, `from_box` 상자에서 마스크를 다시 만들어 맞춤,
`box_only` 상자만 있어 각도 없음, `fit_*` 외부 모델의 마스크를 윗면으로 못 맞춰 최소 사각형을 씀.

외부 모델(랩의 Ultralytics 어댑터)용 계약 함수 `cube_from_quad / cube_from_polygon / cube_from_mask / cube_from_box`도 같은 후처리를 쓴다.
`face_px`를 넘기면 옆면 띠를 자르고, `color=`를 넘기면 그 색을 그대로 쓴다(픽셀이 다르면 `class_mismatch`만 붙이고 버리지 않음).
`cube_from_box`는 상자 중앙 색과 비슷한 픽셀로 마스크를 다시 만들어 각도까지 찾는다(실패하면 `box_only`).

### 보정 담당자에게: 윗면 중심과 판 위 점

`center`는 **윗면(높이 25 mm) 위의 점**이다. 판(높이 0) 기준 호모그래피에 그대로 넣으면 주점에서 4.3 % 더 바깥으로 간다
(반경 295 mm에서 약 12.8 mm). 같은 큐브의 판 위 점은 다음과 같다.

```
centre_base = pp + (centre_top − pp) × (1 − 25/601)      # pp = 주점 (보정값, 없으면 영상 중심)
```

탑 위 큐브(k단)는 `25/601` 대신 `25·k/601`. 픽셀→mm 변환이 어느 평면 기준인지 보정 담당과 꼭 맞춰야 한다.

## 4. 색 판정 (`colour.py`)

- **기준색** `proto_red/green/blue/wood`(#rrggbb)와 **기준 판 색** `proto_board`. 같은 사진에서 큐브 윗면과 빈 판을 찍어 넣는다.
- **조명 보정**: 매 프레임 판 색을 재서 `gains = 기준 판 / 지금 판`(채널별)을 구하고, 큐브 색(중앙값)이나 영상 전체에 곱한다.
  sRGB 값의 채널별 배율은 감마가 거듭제곱일 때 선형 빛의 배율과 같고, 채널별 중앙값과도 순서를 바꿀 수 있어서 정확한 보정이다.
- **판·그림자·회색 거르기**: 판 대비 채도(a\*b\* 거리)가 `chroma_min`(8) 미만이면 판·그림자, 채도가 16 미만이면서 판 밝기의 절반보다 어두우면
  팔·바닥·로봇 받침 같은 어두운 회색. "판보다 어둡다"만으로는 절대 나무로 보지 않는다(그림자가 그렇게 생겼다).
- **분류**: a\*·b\*는 그대로, L\*은 0.3배로 가중한 Lab 거리로 가장 가까운 기준색. `max_dist`(45)보다 멀면 `unknown`.
  `color_score` = 가우시안 확률(σ 10) × 가까움.
- 상태 점검(`notes`): 화소 2 % 이상 포화(노출 과다 — 판 색을 믿을 수 없음), 판 L\* 45 미만(노출 부족), 판 채도 12 초과(색 낌), 판을 못 찾음.

## 5. 파이프라인별

### 5.1 `cv.hsv_ranges` — HSV 색 범위

- **발상**: 색마다 H·S·V 각각 하한–상한 게이트(`cv2.inRange`). H는 179→0으로 감기므로 범위 아래쪽이 음수일 수 있다(−12 = 168).
  두 끝이 모두 음수면 감기지 않는다(−20~−5 = 160~175만, 0은 들어가지 않음). 게이트 전에 판이 무채색이 되도록 채널을 맞춘다(`wb_normalise`, 밝기는 그대로 — 랩의 픽셀 정보에서 읽는 HSV 값과 같은 기준).
  겹치면 빨강·초록·파랑이 나무보다 우선(`wood_yields`, 끌 수 있음).
- **중요한 조절값**: `*_h`(H 범위), `*_s`(S 범위: 아래는 흐린 색·판 제외, 나무의 위쪽은 빨강과 구별), `*_v`(V 범위: 아래는 어두운 색 제외).
  공개 전에는 빨강·초록·파랑의 S·V 상한을 255로 고정해 하한만 보여 줬다. 예전 기록의 `red_s_min` 같은 값은 [값, 255]로 읽는다.
- **대회 날**: 랩 픽셀 정보로 실제 큐브 윗면의 H·S·V를 읽어 범위를 맞춘다. 그늘진 큐브까지 잡히도록 V 최소를 낮게(30~60).
  나무가 판으로 새면 `wood_s` 아래쪽을 올리고, 빨강과 섞이면 `wood_h` 위·`red_h` 아래 경계를 조정.
- **디버그**: `mask`(게이트 통과 픽셀), `hsv`(H를 색상으로 S를 밝기로), `candidates`.
- **측정**: 기본 장면 99.8 %, 어려운 조명 98.9 %. 나무 기본값(H 6~30, V ≥ 70)은 연구 문서 값(H 10~30, V ≥ 120)을
  합성 장면 나무 윗면 분포(H 1백분위 10.3, V 1백분위 80)에 맞춰 넓힌 것이다. 연구 값 그대로면 어려운 조명 94.3 %였다.
  어둡게 찍히면 S·V 문턱 아래로 떨어지는 것이 이 방식의 본질적 약점이다.

### 5.2 `cv.board_diff_lab` — 판 차이 + Lab 최근접색

- **발상**: 보정한 영상에서 판과 a\*b\* 거리가 `t_chroma_hi`(18)보다 큰 픽셀을 씨앗으로, `t_chroma_lo`(10)보다 크면서 씨앗과 이어진 픽셀까지 전경으로 본다.
  전경 픽셀마다 a\*b\*로 가장 가까운 기준색을 붙인다(`t_dist` 밖은 배경). 두 판정은 8비트 (a\*, b\*)에만 달려 있어 65,536칸 표 하나로 한 번에 끝낸다.
- **중요한 조절값**: 기준색 5개(가장 중요), `t_chroma_lo`(나무와 판을 가르는 값: 옅은 나무가 빠지면 낮추고, 판 가장자리·그림자가 잡히면 올림), `t_chroma_hi`.
- **대회 날**: 실제 큐브 4색 + 빈 판을 같은 사진에서 찍어 기준색을 넣는다. `labels` 레이어에서 픽셀 색이 맞게 칠해지는지 본다.
- **디버그**: `chroma`(판과의 채도 차이 색지도), `foreground`(전경 마스크), `labels`(픽셀별 색), `candidates`.
- **측정**: 기본 99.8 %, 어려운 조명 99.6 %, 오검출 0.

### 5.3 `cv.edge_quads` — 윤곽으로 닫힌 사각형

- **발상**: L\*·a\*·b\* 세 채널 Canny(a\*·b\*는 8비트 저장 배율 차이 2.55를 맞춘 문턱), 틈 메우기 후 윤곽이 둘러싼 영역 가운데
  넓이 0.45~4.5면, 최소 회전 사각형의 긴 변 3.6면 이하(붙은 큐브 한 줄 3개까지; 합성에서 2.5~3.0면),
  면 하나 크기면 최소 사각형을 80 % 이상 채움(더 크면 볼록 껍질 대비 조밀함), 안쪽 색이 고른(a\*b\* 표준편차 ≤ 12) 영역.
  색은 찾은 뒤 픽셀에서 읽고, 판 색이면 버린다(빈 위치 표시, 홈 사이 칸).
  길이는 돌린 사각형에서 잰다: 화면 축에 맞춘 상자로 재면 30~60° 돌아간 같은 색 2×2 묶음(똑바로 2.8면)과 한 줄 3개가 통째로 빠졌다.
- **중요한 조절값**: `canny`(낮추면 희미한 나무 윤곽까지, 잡선도 늘어남), `edge_seal`(윤곽 틈 메우기), `min_rectangularity`, `t_uniform`.
- **대회 날**: 움직이는 영상보다 멈춘 프레임에서 강하다. 나무를 놓치면 `edges` 레이어에서 윤곽이 닫혔는지 보고 `canny` 낮은 값을 내린다.
- **디버그**: `edges`, `regions`(초록 통과·빨강 모양 탈락·주황 색 불균일), `candidates`.
- **측정**: 기본 98.5 %, 어려운 조명 97.6 %, 중심 오차가 가장 작다(평균 0.45 px). 놓치는 것은 대부분 판과 대비가 약한 나무.

### 5.4 `cv.lab_autocluster` — Lab 자동 군집

- **발상**: 보정한 영상을 1/4로 줄여 판 근처 색(`board_radius`)을 빼고, 남은 픽셀을 (a\*, b\*, 0.3·L\*)로 k-평균(OpenCV, 시드 고정 → 같은 입력이면 같은 결과).
  군집 중심마다 가장 가까운 기준색 이름(무채색 중심은 '기타'). 전체 해상도에서는 픽셀마다 가장 가까운 중심의 이름.
  줄이면 픽셀이 남지 않는 화면(1/4 배율이면 한 변 4 px 미만)은 군집 없이 빈 결과와 메모를 낸다.
- **중요한 조절값**: `k_clusters`(장면 색 수 + 여분), `name_max_dist`, `board_radius`, `init`(기준색에서 시작하면 더 안정).
- **대회 날**: 결과 `notes`의 "군집 중심: 빨강 #…" 이 그 조명에서 실제 색이다. 다른 파이프라인의 기준색으로 옮겨 쓸 수 있다.
- **디버그**: `clusters`(군집 중심 색으로 칠함), `labels`, `candidates`.
- **측정**: 기본 99.6 %, 어려운 조명 99.3 %. 가장 느리다(p50 22~26 ms).

## 6. 대회 날 맞추는 순서

1. 경기 카메라·경기 자세(601 mm, 1280x720)로 큐브 4색 + 빈 판이 함께 보이는 사진을 찍는다(가능하면 노출·화이트밸런스 고정).
2. 랩 뷰어의 색 고르기로 `proto_red/green/blue/wood`를 각 큐브 윗면에서, `proto_board`를 같은 사진의 빈 판에서 찍는다.
3. **검출 영역(ROI)**: 바구니 바닥 세 곳과 기둥을 제외 다각형으로 그린다. 포함 다각형을 그린다면 **경기장 가장자리보다 넉넉히** —
   가장자리 큐브의 윗면은 원근 때문에 판 경계 밖(바닥 위)으로 밀려 보인다. 크기 검사(`max_area_ratio`)는 두 번째 방어선일 뿐이다
   (팔이 바닥을 가리면 바닥 조각이 큐브 크기가 될 수 있다).
   다각형끼리 겹치거나 하나가 다른 하나 안에 있어도 된다: 포함 다각형은 합쳐서, 제외 다각형도 합쳐서 뺀다.
4. `face_px`: 큐브 한 변을 화면에서 재어 61과 다르면 고친다(카메라 높이·해상도가 다르면 달라짐). 탑 윗면은 저절로 더 크게 맞춘다.
   범위는 10~400 px. 해상도에 비례한다(합성: 640x360이면 30.6, 3840x2160이면 183.7). 범위에 막혀 실제보다 크게 넣으면 모든 큐브가 `partial`이 된다.
5. 같은 사진·영상에서 네 파이프라인을 실행 기록으로 남기고 비교 화면에서 본다.

## 8. 합성 장면 (`cubevision/synth.py`)

- `make_scene(seed, mission="A"|"B", size=(1280, 720), **variation) -> (BGR, 정답 목록)`. 같은 시드·인자면 같은 그림.
  정답: `color`, 윗면 `quad`, `center`, `angle`, 그리고 `level`(탑 단), `visible`(가려지지 않은 윗면 비율), `arena_mm`.
  변형: `paper`("top"|"all"), `touching`, `tower`(0~9), `arm`, `marks`, `shadows`, `noise`, `blur`, `jpeg`, `light`, `vignette`, `exposure`, `wb`,
  `cubes=[{"color","x","y","angle","level"}]`(경기장 mm로 직접 배치). `synth.CLEAN`은 잡음·그림자·팔 등을 모두 끈 설정.
- 기하: 핀홀, f = 1410.6 px(1280 폭 기준), 렌즈 601 mm, 경기장 좌표(원점 = 로봇 축, 렌즈 아래 점 (−13.1, 131.4) mm)는 규칙 도면 그대로.
  큐브는 실제 3D 상자로 그려 옆면이 원근대로 보인다. 2배로 그린 뒤 줄여 경계가 부드럽다.
- `sample_assets(out_dir)`: 미션 A·B 정지 사진(JPEG)과 5초 30 fps 영상(mp4v, 150프레임, 큐브 3개를 차례로 옮기고 팔이 따라감). 약 6.4~6.6초 걸린다.

## 9. 연구 문서와 다르게 한 것 (측정으로 바꾼 이유)

| 연구 문서 | 구현 | 이유 |
|---|---|---|
| 판 기준 좌표: a′ = a − a₀ (Lab 이동)으로 비교, 판·어두움 거부용 기준색 | 영상(또는 큐브 색)을 판 기준 채널 배율로 되돌린 뒤 비교, 거부는 채도 하한 + "어둡고 채도 약함" 규칙(큐브 색과 픽셀 둘 다) | Lab 이동은 강한 색 낌에서 어두운 회색(기둥·바닥)을 판 대비 채도가 있는 것처럼 만들어 나무 오검출을 냈다. 포화 장면이 섞인 첫 어려운 조명 세트에서 `cv.lab_autocluster` 장당 0.79개 → 배율 보정 후 0.31개. 남은 것은 포화 장면과 어두운 픽셀 잡음이어서 포화 경고와 픽셀 단위 어두운 회색 규칙을 더했고, 지금 세트(포화 없음)에서 0 |
| 판 측정: HSV S < 40 고정 | 밝은 픽셀 가운데 S 하위 40 % (최소 40까지) | 강한 색 낌에서는 판의 S가 40을 넘어 판을 못 찾았다 |
| 개수: n = round((E − 띠)/L) | 1.6면 미만은 한 개 | 탑 윗면(1.05~1.53면)을 두 개로 나누지 않기 위해 |
| 거친 각도: minAreaRect만 | 여러 개로 보이는 덩어리에서 minAreaRect와 윤곽 방향(4θ 평균)이 8° 넘게 다르면 윤곽 방향 | 반 칸 어긋나게 붙은 두 큐브의 최소 사각형은 큐브와 정렬되지 않는다(각도 오차 28°). 단일 큐브는 minAreaRect가 더 정확(윤곽 방향은 띠 때문에 최대 5° 치우침) |
| 나누기: 이음매 → 워터셰드 → k-평균 | 꽉 찬 묶음 타일 → 한 줄 어긋난 묶음은 윗면 폭으로 자르기 → 워터셰드 → k-평균 (이음매 단계는 안 만듦) | 평평하게 붙은 같은 색 큐브는 이음매가 거의 없고, 한 줄 자르기가 정확 |
| 구멍 메우기: 항상 | 메운 넓이가 1.5배 이하일 때만 | 빨강 큐브 둘레의 섞인 색(분홍) 픽셀 고리가 메워져 가짜 나무 큐브가 됐다 |
| — | 윗면 사각형의 50 % 미만만 덩어리로 덮이면 버림(`hollow`), 다른 큐브 실루엣 안의 후보 제거 | 같은 고리·옆면 띠 문제 |
| edge_quads Canny 문턱 공통 | a\*·b\* 채널은 문턱 ÷ 2.55 | 8비트 Lab은 L\*만 2.55배로 저장. 나무는 판과 주로 b\*에서 다르다(당시 48장에서 `cv.edge_quads` 재현율 91.5 → 96.3 %, 놓친 것은 대부분 나무) |
| board_diff_lab `bg_mode = reference`, lab_autocluster `recluster_every`·`gmm`, 8단계 영상 추적 | 만들지 않음 | 파이프라인은 프레임마다 상태가 없어야 한다(계약). `cv2.ml.EM`은 OpenCV 5에 없음 |
| `angle_method` profile/grad4, `refine = edges` | 만들지 않음(선택 사항) | 기본 장면 각도 오차가 이미 평균 0.3° |
| `cv.hsv_ranges` 나무 H 10~30, V ≥ 120 | H 6~30, V ≥ 70 | 합성 나무 윗면의 1백분위가 H 10.3, V 80. 어려운 조명 재현율 94.3 → 98.9 %, 오검출 0 그대로 |
| `cv.square_fit` | 만들지 않음 | 우선순위 지시: 네 개를 먼저 완성. 창마다 회전 템플릿 묶음이 필요해 30 ms 예산을 넘길 것으로 보았다 |

## 10. 확인하지 못한 것

- 실제 사진·영상에서의 정확도(합성뿐). 기준색 기본값은 인쇄 색 추정이다.
- 노출 과다로 판이 포화된 프레임: 판 색을 믿을 수 없어 경고만 낸다(측정한 범위 밖).
- 렌즈 왜곡, 주점이 영상 중심이 아닐 때(20 px 정도는 무해하다고 연구 문서가 계산).
- 화면 가장자리에 잘린 큐브(`touches_border`)의 정확도 — 합성 장면은 큐브를 화면 안에만 둔다.
- 팔 색이 빨강·주황·파랑·나무에 가까울 때의 오검출(합성 팔은 어두운 회색).
- 9단 탑처럼 아주 큰 윗면과 큰 옆면 띠의 조합(탑은 4단까지만 측정).
- 모든 면이 종이인 같은 색 L자 3개에서 큐브 하나의 중심이 8 px 남짓 벗어나는 원인(7절 끝 표, 원인은 아직 안 봄).
- 1280x720이 아닌 해상도의 정확도: 합성 장면 한 장씩만 봤다. `face_px`를 맞게 넣으면 640x360에서 9개 모두(중심 최대 1.2 px),
  3840x2160에서 9개 모두(개수만 확인), 어느 쪽도 `partial` 없음.
