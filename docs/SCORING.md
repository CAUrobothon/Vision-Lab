# 채점 — 정답셋 대비 평가 규칙

승인: 2026-11-27 (설계 2차 검토 반영). 이 문서가 채점 구현의 기준이다. 규칙을 바꾸면 이 문서부터 고친다.

## 0. 전제

- 정답셋은 **AI 보조 이미지 근사 라벨**이다(`label_kind`: approximate image-plane geometry, not calibrated physical ground truth).
  작은 오차 차이로 모델 우열을 단정하지 않는다. 차이는 §5의 paired bootstrap 구간으로만 판정한다.
- 허용 오차 5 px / 5° / 5 px RMS는 **잠정 기준**이다. 화면에서 바꿀 수 있고, 로봇 실제 허용 오차가 아니라고 항상 표시한다.
- 평가 범위는 항상 **정답셋 전체**(410장 정답셋이면 410장)다. 잘림 여부로 범위를 나누는 선택지는 두지 않는다.

## 1. 정답셋

지원 형식 두 가지. 큐브 필드는 같고, 410장 형식에만 증강 정보가 있다.

| 형식 (`metadata.schema_version`) | 이미지 | 큐브 | 기하 유효 큐브 |
|---|---|---|---|
| `robothon_top_face_gt_v1.1` | 41 | 328 | 318 |
| `robothon_top_face_gt_augmented_v1.0` | 410 | 3,280 | 3,180 |

이미지마다 읽는 값:

| 값 | 출처 | 없을 때 |
|---|---|---|
| sha256 | `sha256` | — (필수) |
| 파일 이름 | `filename` | `media`의 마지막 부분 |
| 증강 종류 | `augmentation.name` | `"original"` |
| 원본 추적 | `source_sha256` | 자기 `sha256` |
| 배치 묶음 | `layout_group` | — (필수, bootstrap 단위) |
| 근접 쌍 | `near_top_face_pairs` (큐브 id 쌍 목록) | 빈 목록 |
| 큐브 | `frames[0].cubes` | — |

큐브마다 읽는 값: `id`, `color`(red/green/blue/wood), `valid_geometry`, `center`, `quad`, `angle`, `detection_match_point`,
위치 `region`(없으면 `approximate_region`), `image_side`, `flags`.
기하 무효 큐브(410장 기준 100개 = 살짝 잘림 90 + 경계 불확실 10)는 center/quad/angle이 비어 있고
`detection_match_point`(보이는 꼭짓점 기반 근사점)만 있다.

### 1.1 이미지 연결

- 정답 이미지와 데이터셋 미디어는 **sha256이 정확히 같을 때만** 자동으로 연결한다.
- sha256이 안 맞는 정답 이미지는 "연결 안 됨"으로 보여 주고, 파일 이름이 같은 미디어를 **후보**로만 제시한다.
  후보는 사용자가 확인(항목별, 또는 목록을 본 뒤 "후보 모두 연결")해야 연결된다. 확인된 연결은 방식 `confirmed`로 기록한다.
- 한 정답셋 안에서 미디어 하나는 정답 이미지 하나에만 연결된다.
- 같은 파일(파일 sha256 동일)을 같은 데이터셋에 다시 올리면 새 정답셋을 만들지 않고 기존 것을 알려 준다.
  내용이 다른 정답셋은 각각 따로 보관한다(예: 41장판과 410장판).

## 2. 매칭 (이미지 하나 안에서)

- 정답 큐브 **전부**(기하 무효 포함)와 그 이미지의 검출 큐브를 일대일로 짝짓는다.
- 거리 = ‖검출 `center` − 정답 `detection_match_point`‖ (px).
- 게이트 g = 29 px(조정 가능). d > g인 쌍은 짝이 될 수 없다.
- 게이트 안에서 **짝 수를 최대화하고, 그 안에서 거리 합을 최소화**한다(헝가리안, 허용 안 되는 칸에 큰 비용).
- 색은 매칭에 쓰지 않는다.
- 짝이 안 된 정답 = 미검출(FN), 짝이 안 된 검출 = 오검출(FP).

## 3. 지표

| 축 | 지표 | 분자 / 분모 | 410장 기준 분모 |
|---|---|---|---|
| 종합 | **허용 오차 충족률** | 통과한 기하 유효 정답 / 기하 유효 정답 | 3,180 |
| 종합 | **이미지 전체 기준 충족률** | 통과한 이미지 / 이미지 | 410 |
| 객체 검출 | Recall | 짝 수 / 정답 수 | 3,280 |
| 객체 검출 | Precision | 짝 수 / 검출 수 | — |
| 색상 분류 | 색상 정확도 | 색이 맞은 짝 / 짝 수 | — |
| 윗면 추출 | 꼭짓점 RMS 오차 | 유효 출력 수 n, 중앙값, P95 | ≤ 3,180 |
| 윗면 추출 | 중심 거리 오차 | 유효 출력 수 n, 중앙값, P95 | ≤ 3,180 |
| 윗면 추출 | 회전각 오차 | 유효 출력 수 n, 중앙값, P95 | ≤ 3,180 |
| 처리 성능 | 이미지당 처리 시간 | 실행된 이미지 수 n, 중앙값, P95 (ms) | ≤ 410 |

정의:

- **색**: 검출 색이 정답 색과 같으면 정답. `unknown`은 오답. 혼동표(정답 4색 × 검출 5값)를 함께 낸다.
- **중심 거리 오차** = ‖검출 `center` − 정답 `center`‖. 검출 center가 유한한 두 수일 때 유효.
- **회전각 오차** = min(d, 90 − d), d = |a − b| mod 90. 검출 `angle`이 유한한 수일 때 유효.
- **꼭짓점 RMS 오차** = min over k∈{0,1,2,3} √(¼ Σᵢ ‖p₍ᵢ₊ₖ₎ mod 4 − gᵢ‖²). 검출 `quad`가 유한한 점 4개일 때 유효.
  (정답은 맨 위 꼭짓점부터, 실험실 출력은 x+y가 가장 작은 꼭짓점부터 시계 방향이라 순환 정렬이 필요하다.)
- 세 기하 오차는 **기하 유효 정답과 짝지어진 검출**에서, **지표마다 독립적으로** 유효 출력만 모아 계산한다.
  quad가 없어도 center와 angle이 있으면 그 둘은 통계에 들어간다. 각 지표의 n을 함께 보인다.
- **허용 오차 충족률**: 기하 유효 정답 하나가 통과하려면 짝이 있고, 색이 맞고, 중심 ≤ τc, 회전각 ≤ τa, 꼭짓점 RMS ≤ τv를 모두 만족해야 한다.
  필수 출력(center, angle, quad) 중 하나라도 없으면 실패다.
- **이미지 전체 기준 충족률**: 이미지 하나가 통과하려면 정답 전부에 짝이 있고, 색이 전부 맞고, 기하 유효 정답은 전부 위 기하 기준을 통과하고,
  오검출이 0개여야 한다. 기하 무효 정답은 짝과 색만 본다.
- 분위수는 선형 보간(numpy 기본)이다. 값이 없으면 "—"로 표시하고 0으로 채우지 않는다.

기본값: τc = 5 px, τa = 5°, τv = 5 px, g = 29 px.

## 4. 배치 상태

- **완료 배치**: 평가 대상 이미지의 실행이 모두 `done` 또는 `failed`다.
  `failed` 실행은 검출 0개로 보고 그 이미지의 정답을 모두 미검출로 센다. 처리 시간 통계에서는 빠진다.
- **미완료 배치**: `queued`, `running`, `cancelled`가 하나라도 있거나, 평가 대상 이미지 중 배치에 없는 것이 있다.
  미완료 배치는 끝난 이미지로 **중간 점수**만 보여 주고 "중간 결과 · 순위 제외"로 표시한다. 최종 순위와 차이 판정에는 넣지 않는다.
- 동영상은 정답이 없어 채점하지 않는다(건너뛴 수만 표시).

## 5. 비교와 차이 판정

- 비교는 **같은 정답셋, 같은 기준(τc, τa, τv, g), 같은 평가 이미지 집합**의 완료 배치끼리만 한다. 조건이 다르면 이유를 보인다.
- 기준 배치 A 하나를 고르면 다른 배치 B마다 지표별로 **paired bootstrap**을 한다.
  - 재표집 단위는 `layout_group`이다(410장 정답셋은 35개 그룹. 증강 이미지는 원본과 같은 그룹이라 독립 표본으로 세지 않는다).
  - 그룹을 복원 추출로 다시 뽑아 고른 그룹의 이미지 전부로 A와 B의 지표를 계산하고 차이 B − A를 모은다(같은 표본을 두 배치에 쓴다).
  - 차이의 95% 백분위 구간을 낸다. 구간이 0을 포함하면 **차이 불분명**, 아니면 높음/낮음.
  - 각 배치의 개별 구간이 겹치는지로는 판단하지 않는다.
  - 기본값: 반복 2,000회, 수준 95%, 시드 0(조정 가능, 같은 설정이면 같은 결과).

## 6. 조각별 성능

| 조각 | 값 | 단위 |
|---|---|---|
| 증강 | `augmentation.name` 10종(original 포함) | 이미지 |
| 위치 | center / middle / outer (`region`, 기하 무효는 `approximate_region`) | 큐브 |
| 좌우 | left / right (`image_side`) | 큐브 |
| 색 | red / green / blue / wood (정답 색) | 큐브 |
| 근접 | `near_top_face_pairs`에 든 큐브 / 아닌 큐브 | 큐브 |
| 경계 약함 | `flags`에 `weak_boundary` 있음 / 없음 | 큐브 |

- 이미지 단위 조각(증강)은 모든 지표를 낸다.
- 큐브 단위 조각은 정답 큐브에 붙는 지표만 낸다: Recall, 색상 정확도, 허용 오차 충족률, 세 기하 오차.
  Precision, 이미지 충족률, 처리 시간은 큐브 단위 조각에서 정의되지 않는다.
- 칸마다 n을 함께 보인다.
- **증강 영향**: 증강 v마다 Δ = 지표(v 이미지) − 지표(같은 원본의 original 이미지).
  `source_sha256`으로 짝지은 원본들만 쓰고, 구간은 layout_group 단위 paired bootstrap이다.

## 7. 내보내기

- `cubes.csv`: 정답 큐브 한 줄 + 오검출 한 줄. 열은 배치, 이미지, 증강, 원본 sha256, 정답 id/색, 검출 색, 짝 거리,
  중심/각도/꼭짓점 오차, 통과 여부, 조각 속성(위치, 좌우, 근접, 경계 약함, 기하 유효)이다.
- `summary.csv`: 배치 × 지표 한 줄씩. n, 값, 중앙값, P95, 상태(완료/중간)를 포함한다.
- 두 파일 모두 BOM이 있는 UTF-8이고, 쓴 기준값을 머리 주석이 아니라 열로 남긴다.

## 구현 메모

규칙이 아니라 구현 사실이다. 규칙은 위 절들이 기준이다.

- 코드: 계산은 `backend/cubevision/gt.py`(읽기) · `score.py`(매칭 · 지표 · bootstrap · CSV 행). 실험실 쪽은 `backend/lab/gtsets.py`
  (정답셋 저장 · 연결 · 정리)와 `backend/lab/scoring.py`(배치별 평가 이미지 고르기 · 캐시 · API 객체 · CSV), 경로는 `lab/api/gt.py` ·
  `lab/api/score.py`. 저장 구조와 API 목록은 `docs/DESIGN.md` §4 · §5.
- 한 곳에만 있는 규칙: §3의 통과 규칙은 `CubeScore`(기준별 `center_ok` · `angle_ok` · `vertex_ok`, `geom_ok`, `passed`, `outcome`)에만
  있고, 이미지 통과 · 미검출/오검출/색 틀림/기하 실패 수(`outcome_counts`) · 화면의 큐브 판정은 모두 이것을 읽는다. §3의 비율과
  분포는 이미지마다 센 값(`_image_counts` · `_image_samples`, 큐브 조각은 `_cube_counts`)을 더해 만들고, `aggregate`와 bootstrap
  재표집이 같은 값을 쓴다. 기준값의 기본값과 한계는 `Criteria`(+ `MAX_BOOTSTRAP_REPS`)를 요청 스키마가 그대로 옮긴 것이고
  `GET /api/score/criteria`가 그 스키마를 읽어 준다.
- 저장: 올린 JSON은 바이트 그대로 `data/gt/gt-<id>.json`. 이미지 목록은 `gt_images`에 색인한다(연결 계산용).
  sha256 연결은 저장하지 않고 요청마다 데이터셋의 현재 이미지에서 구한다. `gt_links`에는 확인한 연결만 있고, 그 미디어가 데이터셋에
  없거나 sha256 연결과 겹치면 무시하고 이유를 `links.ignored`로 알린다. 확인은 파일 이름이 같은 후보가 아닌 데이터셋 이미지도 받는다
  (사용자가 이름을 바꾼 파일).
- 평가 이미지: 배치 범위(데이터셋 전체 또는 `batches.folder`와 그 아래 폴더) 안의, **지금** 연결된 이미지. 범위는 지금의 폴더
  배치로 판단하므로 배치 뒤에 넣은 미디어는 "배치에 없음"(`pending.missing`)이 되어 배치를 중간 결과로 만든다.
  이미지마다 그 배치의 실행 1개(같은 미디어가 둘이면 최신)의 상태로 판단한다: `done` → frame 0의 큐브와 ms, `failed` → 검출 0개,
  `queued` · `running` · `cancelled` 또는 실행 없음 → 미완료(이유별 수). `done`인데 frame 0이 없으면 `failed`처럼 읽는다.
- 범위가 정답셋 전체가 아닌 배치(폴더 배치, 연결 안 된 정답 이미지가 있는 경우)는 포함률이 1 미만이고 최종 순위에 들지 않는다.
  기준 배치를 따로 주지 않으면 요청 목록 순서(비우면 최신순)에서 처음 나오는 완료 · 전체 포함 배치가 기준이다. 준 기준이 중간 결과면
  그 이유(`reference_note`)와 함께 기본 기준으로 바꾼다. 다른 데이터셋의 배치는 400으로 거절한다(한 요청 = 정답셋 하나).
- 캐시(프로세스 메모리, 크기 제한, `lab/cache.py`의 LRU 하나. 같은 계산을 동시에 요청하면 한 번만 계산하고 나머지는 기다린다):
  끝난 실행의 frame 0 검출(파싱한 값)은 (실행 id, finished_at)마다 한 번이라 τ · g를 바꾸면 매칭만 다시 한다. 정답셋마다 최근
  기준값 3세대(τc · τa · τv · g)를 두고, 세대마다 이미지 채점(정답 이미지 · 실행마다, 실행의 status · frames_done · finished_at이
  바뀌면 다시)과 배치별 지표 · 조각(채점된 이미지와 실행 상태의 지문이 바뀌면 다시)을 둔다. 배치별 항목은 배치 id로 하나라서
  중간 배치를 폴링하면 앞 항목을 바꿔 쓴다. bootstrap 설정(반복 · 수준 · 시드)만 바꾸면 이미지 · 지표 · 조각은 그대로다.
  증강 영향은 (기준 전체, 배치, 지문)마다, paired bootstrap은 (기준 전체, 기준 배치, 배치, 두 지문)마다 한 번.
- bootstrap의 A쪽(`BootstrapSide`: A의 지표, 추첨, 재표집마다의 값)은 A의 이미지와 추첨(그룹 · 반복 · 시드)에만 달려 있어 한 번
  만들어 다시 쓴다: 기준 배치의 것은 비교하는 배치 전부가(캐시), 같은 원본들의 것은 그 원본의 증강 9종이 함께 쓴다. 결과는 매번
