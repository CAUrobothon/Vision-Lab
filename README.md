# Vision Lab

로보톤(2026-11-29) 큐브 인식용 비전 모델을 이미지·영상으로 실험, 실험결과, 실험기록을 쌓아 두는 로컬 웹앱

## 실행

```bash
cd ~/Desktop/로보톤/vision-lab
./run.sh            # → http://127.0.0.1:8010
```

- 화면이 바뀌었으면 `run.sh`가 먼저 빌드한다. 끄려면 실행한 터미널에서 Ctrl+C.
- 이미 켜져 있으면 "포트 8010 을 이미 다른 프로그램이 쓰고 있습니다"가 나온다. 그대로 브라우저에서 열면 된다.
  백그라운드로 켜 둔 서버를 끄려면 `lsof -ti tcp:8010 | xargs kill`.
- 데이터(올린 파일, 기록, 가중치)는 `data/`에 쌓인다. 서버를 껐다 켜도 그대로 남는다.

## 쓰는 법

1. **올리기** — 작업대 아무 곳에나 이미지·영상을 끌어다 놓거나, ⌘V로 붙여넣거나, 왼쪽 "올리기".
   처음이라면 "합성 샘플 넣기"로 시험용 사진 2장·영상 1개를 넣을 수 있다(태그 `sample`).
2. **모델 고르기** — 오른쪽 위. 내장 OpenCV 파이프라인 4개 + 직접 올린 `.pt`.
   파이프라인은 슬라이더를 움직이는 즉시 미리보기가 다시 그려진다(저장 안 됨).
3. **크게 보기** — 휠로 확대(커서 기준), 끌어서 이동, `0` 맞춤, `1` 100 %, `F` 전체 화면.
   오른쪽 위 레이어 버튼으로 윗면 사각형·중심·각도·라벨·디버그 레이어(마스크)를 켜고 끈다.
   십자 버튼은 픽셀 정보(RGB · HSV · Lab) — 슬라이더 값과 같은 단위다.
4. **색·영역 맞추기** — 색 기준 파라미터의 "이미지에서 고르기"로 실제 큐브 윗면 색을 찍는다.
   "검출 영역"에서 바구니 바닥·기둥을 제외 다각형으로 그린다(클릭으로 점, Enter로 닫기, Esc 취소).
4-1. **ChatGPT 등에게 파라미터 받기** — 프리셋 옆 "JSON". "ChatGPT용 설명 복사"로 지금 모델·파라미터(지금 값·범위·뜻)를 복사해
   ChatGPT에 주고, 받은 JSON(`{"model": "cv.…", "params": {…}}` 또는 파라미터만)을 붙여넣고 "적용".
   코드 블록·설명 문장·끝 쉼표가 섞여 있어도 읽는다. 서버가 실행 때와 같은 규칙으로 값을 맞추고,
   범위에 맞춰 바뀐 값과 모르는 이름을 알려 준다. 다른 모델 키가 적혀 있으면 그 모델로 바꾼다.
5. **기록으로 저장** — 지금 파라미터로 실행 기록을 남긴다. 영상은 "영상 전체 실행"(구간·N프레임마다 지정 가능).
   `.pt` 모델은 "실행". 기록은 아래 띠와 "기록" 화면에 쌓인다.
6. **기록 관리** — "기록" 화면에서 별표·메모·태그, 필터, PNG/MP4 내보내기, 삭제, "파라미터 바꿔 다시 실행".
7. **비교** — 기록 두 개를 체크하고 "비교": 나란히(확대·재생 위치 연동) 또는 겹쳐 보기, 큐브 수·색·시간 차이.
7-1. **데이터셋** — 왼쪽 위 "새로"로 데이터셋을 만들고 고르면 목록이 그 데이터셋만 보여 주고, 그때 올리는(끌어다 놓기·⌘V 포함) 파일은
   그 데이터셋에 들어간다. 이미 있는 미디어는 "선택"으로 골라 "데이터셋에 넣기"(새 데이터셋으로 묶기도 됨)·"여기서 빼기".
   미디어 하나가 여러 데이터셋에 들어갈 수 있고, 데이터셋을 지워도 미디어와 기록은 남는다. "원본 zip"은 원본 파일 전부.
   **일괄 실행 · 결과 받기**: 오른쪽에서 고른 모델·파라미터로 "지금 모델로 전체 실행"(영상은 N프레임마다) → 항목마다 결과가 그려진
   PNG/MP4를 하나씩 받거나 "전체 zip"(그려진 결과 + `results.json` 전체 결과 + `results.csv` 큐브 한 줄씩)으로 받는다.
   항목 이름을 누르면 작업대에서 그 결과를 크게 본다.
8. **학습한 모델 시험** — "모델 · 저장공간"에서 Ultralytics `.pt`(detect / segment / obb)를 올린다.
   클래스 이름이 red·green·blue·wood(또는 빨강·초록·파랑·나무)면 그 색을 쓰고, 아니면 윗면 픽셀로 색을 정한다.
   원본 COCO 가중치(예: `yolo26n-seg.pt`)에는 큐브 클래스가 없어서 아무것도 안 잡히는 것이 정상이다.

대회 날 실제 카메라로 맞추는 순서와 파이프라인별 조절법은 [docs/PIPELINES.md](docs/PIPELINES.md) 6절.

## 내장 파이프라인

| 키 | 이름 | 발상 |
|---|---|---|
| `cv.hsv_ranges` | HSV 색 범위 | 색마다 H·S·V 범위. 가장 빠르고 직관적 |
| `cv.board_diff_lab` | 판 차이 + Lab 최근접색 | 흰 판과 색이 다른 픽셀을 전경으로, 가장 가까운 기준색으로. 처음엔 이것을 기본으로 |
| `cv.edge_quads` | 윤곽으로 닫힌 사각형 | 색을 보지 않고 윤곽이 둘러싼 윗면 크기 사각형을 찾음. 중심이 가장 정확 |
| `cv.lab_autocluster` | Lab 자동 군집 | 판을 뺀 픽셀을 k-평균으로 묶어 색 이름을 붙임. 군집 중심을 기준색 후보로 알려 줌 |

네 개 모두 같은 후처리를 쓴다. 원근 때문에 보이는 옆면 띠를 잘라 **윗면** 사각형·중심·각도(0~90°)를 내고,
붙은 큐브를 나누고, 바구니 바닥 같은 큰 색 영역을 버린다. 합성 장면 측정값(재현율 98~100 %, 중심 오차 평균 0.5~0.9 px,
프레임당 16~22 ms)은 **합성 데이터 기준**이라 실제 사진 성능은 이 랩에서 직접 확인해야 한다.

출력 좌표는 모두 이미지 픽셀이다. `center`는 윗면(높이 25 mm) 위의 점이라, 판(높이 0) 기준 호모그래피에 넣으면
카메라 축에서 4.3 % 바깥으로 간다. 보정 담당과 맞출 공식은 PIPELINES.md 3절 끝.

## 구조

```
backend/cubevision/   순수 OpenCV 패키지 (웹·torch 없음) — 대회 프로그램에서 그대로 import 가능
backend/lab/          FastAPI 서버 · SQLite · 작업자 프로세스 · Ultralytics 어댑터
frontend/             React 19 + Vite 7 화면
data/                 (git 제외) lab.sqlite3, media/, proxy/, thumbs/, weights/, exports/
docs/DESIGN.md        설계 · API · 화면
docs/PIPELINES.md     파이프라인 원리 · 조절법 · 측정
docs/research/        2026-11-25 조사 원문 (모델 · 고전 CV 설계 · 웹 구조 · 디스크)
docs/screenshots/     화면 스크린샷
```

대회 코드에서 쓰는 예:

```python
import cv2
from cubevision.registry import get_pipeline

pipe = get_pipeline("cv.board_diff_lab")
result = pipe(cv2.imread("frame.jpg"), {"proto_red": "#a6312b"})  # 안 준 파라미터는 기본값
for c in result.cubes:
    print(c.color, c.center, c.angle, c.quad)
```

## 알아 둘 것

- 영상은 올릴 때 브라우저와 서버가 같은 프레임을 읽도록 H.264 고정 프레임률 사본(프록시)을 만든다.
  원본은 그대로 보관되고 "원본"으로 내려받을 수 있다. 긴 4K 영상은 변환에 시간이 걸린다.
- 휴대폰 사진은 색 프로파일(Display P3)을 떼어 OpenCV와 같은 색으로 보여 준다.
- `face_px`(윗면 한 변, 기본 61 px)는 경기 카메라(601 mm, 1280x720) 기준이다. 다른 거리·해상도로 찍은 사진은
  큐브 한 변을 재서 고쳐야 한다.
- `.pt` 실행은 Apple GPU(MPS)를 쓰고, 첫 프레임은 모델 적재 때문에 1초 남짓 걸린다(기록에 "첫 프레임"으로 따로 표시).
  가중치 모델은 한 번에 하나만 메모리에 올린다.
